# YuCap — キャプチャビューア

USB キャプチャボード（UVC/UAC 準拠。想定機種：j5create JVA14）の映像・音声を
**「見るだけ＋スナップショット」**に特化した Windows デスクトップアプリです。録画機能は持ちません。

Media Foundation の Capture Engine を使い、プレビューを **GPU で直接ウィンドウへ描画**します。
NV12/P010 をネイティブに扱えるため、DirectShow では届かなかった **1080p120 / 1440p60 / 4K30** が使えます。

## 動作環境

- Windows 10 / 11（x64）
- [.NET 8 デスクトップランタイム](https://dotnet.microsoft.com/download/dotnet/8.0)
- UVC/UAC 準拠の USB キャプチャデバイス

動作確認済み: j5create JVA14（1080p120 NV12）、Windows 11

## インストール

[Releases](https://github.com/Yu5rin/YuCap/releases/latest) から `YuCap.exe` をダウンロードして任意の場所に置くだけです（インストーラ不要）。
設定は `%APPDATA%\YuCap\settings.json` に保存されます。

## 更新

起動時に新しい版を確認し、あれば裏でダウンロードして照合します。視聴は中断されません。
準備ができると画面に通知が出て、**YuCap を閉じたときに置き換わります**（通知のクリックや
**ヘルプ → 再起動して更新** で、その場で再起動して更新することもできます）。閉じ損ねた場合
（強制終了など）は、次回起動時に新しい版へ置き換えてから起動します。
**オプション → 自動で更新する** でオフにでき、オフの間は何も入れません。
**ヘルプ → 更新を確認...** でいつでも手動で確認できます（詳しくは「外部通信について」を参照）。

照合用のハッシュが公開されていない版や、書き込めない場所に置いている場合は、自動では入れず
通知だけを出します。その場合は YuCap を終了してから Releases の新しい `YuCap.exe` で
置き換えてください。設定はそのまま引き継がれます。

## 主な機能

- **自動デバイス選択** — 名前に指定キーワード（既定 `JVA14`）を含む機器を優先。無ければ先頭を使用
- **抜き差し検出と自動再接続** — ケーブルを挿し直すと映像・音声が自動復帰。既定の再生デバイス変更にも追従
- **表示モード** — アスペクト比保持／引き伸ばし／原寸／**整数倍**（ドット絵がボケない）
- **高画質拡大（試験版）** — オプション → 描画方式で「Direct3D」を選ぶと、ウィンドウや全画面が入力より大きいときに
  AMD FidelityFX FSR 1 で拡大します（表示 → 拡大の画質、シャープさも調整可能）。1440p 入力を 4K で見るときなどに効果があります
- **フレーム補間（試験版）** — 表示 → フレーム補間をオンにすると、モニターの更新が映像のコマ数より十分速いとき
  （例: 30 fps の映像を 60 Hz で、60 fps を 144 Hz で、120 fps を 144 Hz で見るとき）に、前後のコマの動きを調べて間のコマを作り、
  更新のたびに新しい絵を出して動きをなめらかにします。モニターの更新が映像のコマ数の 1.1 倍に届かないとき（60 fps の映像と 60 Hz など）や
  低遅延モードのときは自動で働かず、そのままの表示になります。働いているかは情報表示（Ctrl+Shift+I）の「補間」で分かります。
  間のコマを作るために、映像が 1 コマぶん遅れます（30 fps なら約 33 ms）。素早い動きや、物の陰から何かが現れる場面では絵が乱れることがあります
  （Direct3D 描画のとき。初期設定はオフ）
- **映像の調整** — 表示 → 映像の調整で、明るさ・コントラスト・彩度・ガンマを動かしながら確認できます。保存するスナップショットにも反映されます（Direct3D 描画のとき）
- **音ズレ補正** — デバイス → 音ズレ補正で、映像と音のずれを ±300ms の範囲で合わせます。音を早める側は映像を遅らせて合わせるため Direct3D 描画のときに使えます。画面には「いまの遅れ」（映像と音が YuCap と Windows の中で何 ms かかっているか）がリアルタイムで出て、［目安に合わせる］で差がなくなる位置に動かせます
- **遅延の表示** — 情報表示（Ctrl+Shift+I）の「遅延（YuCap 内）」、音ズレ補正の画面、テストレポートに、映像と音が「キャプチャボードから YuCap に届いてから、画面に出る・音が鳴るまで」にかかる時間を出します（映像は Direct3D 描画のとき）。キャプチャボードやテレビの中で生じる遅れは測れないため含まれません。目安として使ってください
- **プロファイル** — 接続元ごと（Switch 2 と PC など）に、映像モード・描画方式・拡大の画質・フレーム補間・表示モード・映像の調整・音ズレ補正・黒い縁の切り取り・低遅延・保存方法をまとめて覚えます。最大9個で、プロファイルメニューか Ctrl+1〜9 で切り替えます。切り替えた後に設定を変えると「変更あり」と表示され、上書きするまでプロファイルは変わりません
- **黒い縁の切り取り** — 表示 → 黒い縁の切り取りで、映像の四辺の黒い縁を数値または「自動で検出」で切り取ります。切り取った絵に合わせて拡大され、スナップショットにも反映されます（Direct3D 描画のとき）
- **表示どおりに保存** — オプション → スナップショット設定で、画面に出ている大きさ（拡大の画質を反映）のままスナップショットを保存できます（Direct3D 描画のとき。一時停止中はソースの大きさで保存します）
- **低遅延モード（試験版）** — オプション → 低遅延モードで、垂直同期を待たずにフレームを即座に表示します。ティアリングを許可できる環境では、ボーダーレスの全画面でインディペンデントフリップ / VRR（可変リフレッシュレート）を使えます（Direct3D 描画のとき。切り替えると映像が一度つながり直ります）
- **回転・左右反転**、**デジタルズーム**（Ctrl+ホイール）とドラッグでのパン
- **全画面 / ピクチャインピクチャ**（不透明度・クリックスルー・表示位置・サイズを設定可能）
- **全画面にするモニター** — 表示 → 全画面にするモニターで、全画面にする画面を選べます（既定はウィンドウがあるモニター）。メイン画面で操作しながら、別のテレビ・モニターに映すといった使い方ができます。選んだモニターが外れているときは、今のモニターで全画面にします
- **テストモード（自動試験）** — ヘルプ → テストモードで、実機（キャプチャカード・テレビなど）の動作を自動で一通り試験し、レポートを作ります。全映像モードの取り込みコマ数、GPU の余裕、コマの出方（カクつき）と VRR の効き、全画面での通知の見え方、FSR の比較画像、HDR 入力、各機能、音声、ダイアログの表示崩れを調べます。レポートは「ピクチャ」の `YuCap\テストレポート\（日時）\report.html` に保存され、試験中に変えた設定は終了後に元へ戻ります（Esc で中止）
- **一時停止**（Space）— 映像を静止し音声も停止
- **スナップショット** — **ソース解像度そのまま**保存（ウィンドウが小さくても4K入力なら4Kで保存、他ウィンドウが重なっても影響なし）。PNG/JPEG、クリップボードへコピー、連写（間隔・枚数指定）
- **音声パススルー** — 音量 0〜500%（ソフトリミッター内蔵で歪みにくい）、ミュート、遅延の実測表示
- **音声の出力先** — デバイス → 音声の出力先で、Windows の既定のほか、好きなスピーカー・ヘッドホンを選べます。選んだ機器が外れたときは Windows の既定に切り替え、戻ると自動で選んだ機器に戻ります
- **グローバルホットキー**（他アプリ使用中でも動作、キー割り当て変更可）
- **カーソル自動非表示**（時間設定可）、**画面スリープ抑止**
- **自動更新** — 起動時に新版を確認し、裏でダウンロード・照合して、閉じたときに置き換え
- **起動をブロックしない** — デバイスの初期化を待たずにウィンドウが出ます。
  未接続でもダイアログは出ず、接続した時点で自動的に映ります
- 日本語 / English UI

## SmartScreen の警告について

配布している exe にはコード署名を付けていないため、初回実行時に Windows SmartScreen の警告
（「WindowsによってPCが保護されました」）が表示されます。**［詳細情報］→［実行］** で起動できます。

心配な場合は、ダウンロードした exe のハッシュがリリースページ記載の SHA256 と一致するか確認してください。

```powershell
Get-FileHash YuCap.exe -Algorithm SHA256
```

## 外部通信について

YuCap が外部と通信するのは**更新確認のときだけ**です。それ以外の通信は一切行いません
（使用状況の送信などはありません）。

- 通信先: GitHub Releases API（`https://api.github.com/repos/Yu5rin/YuCap/releases/latest`）
- タイミング: 起動のたび（起動を妨げないよう非同期で実行）、またはメニューの「更新を確認」を押したとき
- 通信先URLは `settings.json` の `UpdateApiUrl` に持たせてあり、変更・確認できます
  （接続先は GitHub のホストに限定しています。リリース応答には照合用の SHA256 も
  含まれるため、任意のホストを許すとハッシュ検証が意味を失うためです）
- 自動更新は **オプション → 自動で更新する** でオフにできます（オフにすると確認もダウンロードも行いません）

ダウンロードした実行ファイルは `%LOCALAPPDATA%\YuCap\update` に置き、SHA256 を照合します。
置き換える直前にも、もう一度照合します（食い違えば破棄して何もしません）。
照合用の SHA256 が公開されていない版は自動では入れません。
更新は「現在の exe をリネームして退避 → 新しい exe を配置」という手順で行い、
途中で失敗した場合は退避したものを書き戻します（`Program Files` などの書き込めない場所に
置かれている場合は自動では入れず、通知してリリースページを案内します）。

## 操作

| 操作 | 動作 |
|---|---|
| 映像上でホイール / ↑ ↓ | 音量 5% 増減 |
| Ctrl + ホイール | デジタルズーム（Ctrl+0 でリセット、ズーム中はドラッグで移動） |
| ダブルクリック / F11 | 全画面切替 |
| Esc | 全画面・PiP を終了 |
| Space | 一時停止 / 再開 |
| M / 中クリック / ステータスバーの音量をクリック | ミュート |
| Ctrl+S | スナップショット保存 |
| Ctrl+C | スナップショットをクリップボードへ |
| Ctrl+T / Ctrl+B | 常に前面 / ウィンドウ枠なし |
| F10 | メニューバー表示切替 |
| Ctrl+Shift+I | 情報表示の切替 |
| Q（押している間） | FSR と標準の拡大を見比べる |
| Ctrl+1〜9 | プロファイルの切り替え |
| F1 | 操作一覧 |
| 右クリック | コンテキストメニュー |

設定項目はすべて「オプション」メニューにまとまっています。

グローバルホットキー（既定・変更可）: `Ctrl+Alt+S` 保存 / `Ctrl+Alt+M` ミュート / `Ctrl+Alt+P` PiP / `Ctrl+Alt+↑` 音量を上げる / `Ctrl+Alt+↓` 音量を下げる（押し続けると連続で変わります）

## コマンドラインオプション

```
--fullscreen        全画面で起動
--borderless        ウィンドウ枠なしで起動
--topmost           常に前面で起動
--muted             ミュートで起動
--volume <0-500>    音量を指定
--mode <指定>       映像モード指定（例: 1080p120 / 1440p60 / 1920x1080@120）
--list-formats [出力先]   対応フォーマットを書き出して終了
--selftest [出力先]       自己診断を実行して終了
--gpu-bench [出力先]      4K 拡大（FSR）の GPU 負荷を計測して終了（Direct3D）
--interp-probe [出力先] [--mode <指定>] [--stills <フォルダ>]
                    フレーム補間を実機の映像で動かし、補間なしと比べたコマ数・GPU 時間・コマの出方を書き出して終了（Direct3D）
--interp-synth [出力先] --in <画像> [--scale <倍率>] [--stills <フォルダ>]
                    動きが分かっている 2 枚の絵（画像とそれをずらしたもの）で補間の精度と GPU 時間を調べて終了（Direct3D）
--hdr-probe [出力先]      HDR 入力の調査結果（キャプチャ機器の色情報・Windows の HDR 状態）を書き出して終了
--restart-stress [出力先] [回数]   プレビューを何度も作り直し、そのたびに映像が戻るかを調べて終了（Direct3D・既定 40 回。
                    `--fullscreen` で全画面、`--fast` で映像が出る前にもう一度作り直す乱暴な試験）
--test-mode [--display <番号>] [--quick]
                    自動試験（上記）を実行してレポートを作り、終了。--display は試験するモニター
                    （`2` なら `\\.\DISPLAY2`、またはデバイス名・モニター名の一部。省略時は既定の選び方）。
                    --quick は短い簡易版（解像度ごとに 1 モード、計測 2 秒）。レポートの場所は
                    ピクチャ\YuCap\テストレポート\latest.txt に書かれる
--check-update      更新の有無を確認して終了
--help              オプション一覧を表示
```

表示・音量に関するオプションはその回の起動だけに効き、保存された設定は変わりません。

## ビルド

```bash
dotnet build -c Release
```

単一 exe を作る場合:

```bash
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o .
```

ランタイム不要の版が必要なら `--self-contained true`（約 69MB）。

> ビルド前に実行中の YuCap を終了してください（exe がロックされます）。

## 設計メモ（触る前に読む価値のある落とし穴）

- **`UpdateVideo` は必ずワーカースレッドから呼ぶ。** UIスレッドから呼ぶと、MF内部がUIスレッドの応答を
  待つためデッドロックする（全画面化で数秒〜無限に固まる）。戻り値 `S_FALSE (0x1)` は**正常**であり
  失敗ではない。
- **`UpdateVideo` に `dst=NULL`（fill window）を渡してはいけない。** DirectComposition では明示矩形が
  合成ビジュアルのリサイズ契機になっており、NULL だと全画面で何も描画されない。
- **プレビュー描画ストリームに `SetSampleCallback` を設定しない。** フレームがレンダラから奪われ、
  プレビューが真っ白になる。
- **フレーム補間（`Shaders/interp.hlsl`、`D3DRenderer` の `InterpUpdate`）は垂直同期に合わせて動く Direct3D 専用の機能。**
  働く条件は「設定オン・Direct3D・低遅延でない・画面の更新 ≥ 映像のコマ数 × 1.1（一度働いたら × 1.05 まで）」で、
  約 1 秒ごとに描画スレッドが見直す。仕組みは次のとおり。
  - 取り込みスレッドが各コマの到着時刻をなめらかにならした時刻（`Slot.Smooth`、位相ロックループ。到着のばらつきを
    そのまま使うと補間の位置が揺れる）を付ける。働いている間は映像を `ユーザー遅延 + ペーシング余白 + 1 コマ` だけ
    リングに溜め、更新ごとに時刻 T = 今 − その遅延 を求めて、T の直前のコマ A と次のコマ B の間の位置 alpha で絵を作る
    （1 コマぶんの遅延が増えるのはこのため）。
  - A・B を向き変換済みの BGRA とその輝度ピラミッド（1/2〜1/16）にしておき、コマの組が変わったときだけ動き推定を行う
    （次の組では B が A になるので、変換とピラミッドは使い回す）。動き推定は粗い方から細かい方へのブロックマッチングで、
    A(x − v/2) と B(x + v/2) を比べる対称型（4×4 画素ごとに 1 本、8×8 の窓、前の段の動きを候補にして ±1・±0.5 画素で詰め、
    各段の後に 3×3 のメディアンをかける）。
  - 合成は `A(p − alpha·v)` と `B(p + (1 − alpha)·v)` の混ぜ合わせで、2 つが食い違うところ（動きが当たっていない所）は
    近い方のコマをそのまま使う。結果は `_oriented` に書くので、拡大・FSR・スナップショットは今までどおり。
  - 補間が働いていないときの経路（`AdvanceDelayed`）は変えていない。60 fps を 59.94 Hz で見るときのカクつきの対策はそちらに依存する。
- **リフレッシュレートの違うモニターを並べているとき（例: メイン 60 Hz・サブ 144 Hz）、サブの画面の映像の上に何かが重なっていると、
  その間 Windows はサブの画面も約 60 Hz でしか書き換えない。** 映像だけが画面に出ているときは 144 Hz で表示される。
  通知・情報表示・一時停止の画像・ほかのウィンドウが映像に重なっている間がこれに当たり、アプリの中からは避けられない
  （ウィンドウのスワップチェーンでも同じ）。テストモードは測定の間だけ見出しを隠す。
  表示のタイミングは映像のあるモニターの `IDXGIOutput::WaitForVBlank` に合わせる（`VBlankBeat.cs`）。
  `D3DKMTWaitForVerticalBlankEvent` はこの構成でサブのモニターでもメインの間隔を返すため使わない（`--vblank-probe` で確かめられる）。
- 万一 `UpdateVideo` が固着した場合に備え、セッションを分離し、検知したらプレビューを自動再起動する
  仕組みを入れている（`--selftest` で両方の経路を検証できる）。

## 診断

問題が起きた場合は `%APPDATA%\YuCap\yucap.log`（動作ログ）と `error.log`（クラッシュ）を確認してください。
UIスレッドが固まった場合も、別スレッドの監視により `*** UI THREAD STUCK` として記録されます。
